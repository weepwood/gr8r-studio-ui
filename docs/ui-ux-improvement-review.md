# UI 与交互优化评审

日期：2026-11-22  
范围：组件展示站、六个原生 Web Components 的部分边界行为、测试与开发环境。

## 一、结论

项目适合继续定位为**轻量、框架无关的任务管理 / SaaS 后台组件库**，而不是直接扩展成完整的协作产品。本轮保留 CSS + ES modules + Web Components 的结构，没有增加运行时依赖。

原有优势是主题变量完整、命名空间清晰、原生控件基础较好；主要短板是展示站缺少鲜明的视觉入口、任务示例操作后容易丢失状态，以及浏览器层面的交互测试不足。

本轮优先补齐了“看得懂 → 找得到 → 可以操作 → 得到反馈 → 刷新后保留”的体验链路。

## 二、本轮已完成

### 1. UI 与信息架构

- 将首页重组为双栏：左侧产品说明、主次操作与技术特点，右侧为组件组合示意。
- 保留暖中性色与 indigo 强调色，使用字号、留白、边框和表面层级组织内容；深色主题继续共用语义变量。
- 调整侧栏选中态、品牌标记、分组间距，增加 Installation 入口与页尾返回顶部。
- 增加轻量技术特点栏，区分“组件库介绍”和“工作台交互示例”。
- 工作台统计明确标注为示例数据，避免被误认为与下方任务列表实时关联。
- 顶栏增加快捷主题切换、当前章节提示，并根据操作系统显示 Ctrl K / ⌘ K。
- 适配窄屏工具栏与任务行；顶栏提示气泡改为向下展开，避免在视口上沿被裁切。
- 文档语言标记调整为与主要界面文案一致的英语。中文界面属于后续本地化工作，而不是仅修改 `lang` 即可完成。

对应文件：`index.html`、`demo/demo.css`、`demo/demo.js`。

### 2. 任务交互闭环

- 任务标题、编号、分类和描述均可搜索；支持仅看未完成、优先级排序与标题排序。
- 增加搜索空态、全部完成状态及清空筛选入口。
- 动态展示任务数量、完成数及完成比例，补充 progressbar 语义。
- 新建任务保留标题、优先级和描述，点击任务标题可查看详情。
- 提交时校验纯空白标题；标题限制 120 字符、描述限制 2000 字符。
- 新建后清除会隐藏新任务的搜索 / 状态过滤条件。
- 删除后提供 Undo。撤销通知不自动超时；手动关闭、通知栈超过 4 条或刷新页面后，不再保证该次撤销入口可用。它不是历史版本或回收站。
- 列表重绘后恢复键盘焦点；未完成筛选下勾选任务后，焦点回到过滤按钮。
- 任务文本采用 `textContent` 写入，避免把用户输入解释成 HTML。

对应文件：`demo/demo.js`、`demo/state.js`。

### 3. 本地状态与异常兜底

- 在 `gr8r-gallery:v1` 本地存储键中保存任务、主题、强调色和密度。
- 首次访问且未保存主题时参考系统深浅色；之后尊重用户明确保存的选择。
- 加载时验证数据类型、枚举值、重复 ID 与文本长度，任务上限为 200 条。
- 对损坏 JSON、禁用存储及写入失败进行降级处理；失败时提示“仅本次访问有效”。
- 空任务数组不会在刷新后被默认任务重新覆盖。
- 持久化仅属于展示站，不会让组件库消费者默认写入本地存储。

**边界：** 数据没有上传到服务器，不支持跨设备同步、用户身份隔离、实时协作或多标签页冲突合并。不要在公开演示环境中录入敏感信息。

### 4. 可访问性与组件修复

- 新增跳转到正文入口；保留移动导航的遮罩、Escape、焦点限制与 inert 管理。
- 下拉菜单用 ArrowUp 打开时定位最后一个可用项，忽略 `aria-disabled="true"` 的条目。
- 下拉菜单重新打开前清除旧定位结果，避免上一次向上展开影响后续测量。
- 嵌套 Tabs 只管理各自的标签和面板，防止子标签点击改变父级选中态。
- 命令面板重挂载时复用空态节点；键盘选择项滚入可见区域。
- 保护模态窗口切换时的焦点，避免全局快捷键在任务表单上再叠一层命令面板。
- 修复深色主题危险按钮的前景对比色；增强未选中 checkbox / radio 的边界。
- 静态 Kanban 不再显示可拖动光标；只有显式设置 `draggable="true"` 才显示抓取提示，这并不自动实现拖拽逻辑。
- 外观 API 先验证整个更新，再修改属性，防止无效参数导致局部主题已经改变。

对应文件：`src/elements.js`、`src/index.js`、`src/components.css`、`src/tokens.css`。

### 5. 工程与验证

- 开发服务器默认监听 `0.0.0.0`，支持代理预览，并拦截隐藏路径（包括 `.git`）。这仍然只是开发服务器，不是生产文件服务。
- 加入仅开发时使用的 Playwright、依赖锁文件和独立的浏览器测试命令。
- CI 配置补充依赖安装、Chromium 安装、浏览器回归以及失败追踪文件上传。
- 保留 `npm test` 的 Node 测试路径，不要求只检查组件契约的用户安装浏览器。

## 三、验证结果

### 已执行

- `npm run check`：Node 测试及静态构建通过。
- Playwright Chromium：10 个端到端场景通过，覆盖任务创建 / 详情 / 删除 / 撤销、状态持久化、文本安全、搜索与空态、键盘完成、外观记忆、移动导航、下拉菜单、命令面板重新挂载、嵌套 Tabs、资源错误及 `.git` 路径拦截。
- 主内容区在 320、390、760、768、1024、1440px 宽度下未检测到横向溢出。表格 / Kanban 内部的局部滚动仍保留。
- 检查了桌面浅色、深色、移动端首页与移动任务列表截图。
- 增加危险按钮在浅 / 深主题下文字对比度至少 4.5:1 的自动断言。

### 验证限制

当前沙箱无法访问 Playwright 默认浏览器下载源，因此本地执行使用从 npm 临时获取的 Chromium 包和系统库；它们未加入项目依赖或 Git。提交的常规测试流程仍使用 Playwright 官方 Chromium，CI 配置已更新，但**尚未触发远端 CI 或部署**。

本轮没有执行 Firefox、Safari / WebKit、iOS 真机或屏幕阅读器测试，也没有完整 WCAG 审计。已通过的 Chromium 测试不等于跨浏览器认证。

## 四、下一步优化建议（按价值排序）

| 优先级 | 优化方向 | 具体建议 | 收益 / 验收标准 |
| --- | --- | --- | --- |
| P0 | 可复制的组件文档 | 每个组件增加 Preview / Code、属性 / 事件表、受控与非受控使用示例；明确呈现组件与交互组件的区别 | 开发者能从单个组件页面完成接入，不必阅读整份 HTML |
| P0 | 浏览器与无障碍矩阵 | 增加 WebKit、Firefox、axe 扫描及关键键盘路径；对 dialog、combobox、switch 做 VoiceOver / NVDA 检查 | 通过约定的浏览器矩阵；无严重 / 致命自动扫描问题，并留存人工结果 |
| P0 | 公共 API 与生命周期契约 | 为重新挂载、属性变化、禁用状态、焦点返回、事件次数补全真实 DOM 测试；定义 Tabs 动态增删后的刷新策略 | 六个组件都有行为测试；类型声明、文档与运行时一致 |
| P1 | 设计变量维护 | 建立 token 单一来源及生成说明；清理已有 CSS 历史覆盖规则；补充全强调色组合的对比度测试 | 避免重复样式漂移；所有主题组合均可自动检验 |
| P1 | 主题首屏与偏好体验 | 增加无闪烁初始化、显式“跟随系统”选项、跨标签页同步；提供重置示例数据 / 清理本地状态 | 刷新无明显浅深色跳变；用户能清楚撤销自定义设置 |
| P1 | 文案和国际化 | 为演示站与组件默认文案建立 en / zh-CN 字典，统一错误、空态、菜单、通知及辅助技术名称 | 切换语言后界面和 accessible name 一起变化；避免仅翻译可见文字 |
| P1 | 表单示例的真实反馈 | 将表单展示区升级为可提交示例，覆盖成功、失败、校验、只读、禁用状态 | 每个交互例子都有可观察结果，而不是仅有静态外观 |
| P1 | 发布与接入 | 补充 CHANGELOG、发布前包内容检查、类型检查、React / Vue / Vite 使用示例和版本策略 | 在干净工程中能安装并完成渲染、主题及自定义事件订阅 |
| P2 | 高级数据交互 | 视真实需求添加表格排序 / 分页 / 批量操作；看板若实现拖拽，必须提供键盘移动替代 | 控件承诺与能力一致；无鼠标也能完成所有操作 |
| P2 | 业务数据层 | 若要从组件库升级成产品，再设计认证、服务端存储、权限、冲突处理与错误重试 | 数据可跨设备同步、权限隔离可测试、失败可恢复；不只替换 localStorage |
| P2 | 性能与大数据 | 先测量布局、长任务和 DOM 数量，再决定是否引入按 ID 更新、分页或虚拟列表 | 以实际数据量的交互延迟为准；当前 200 条演示上限不急于加框架或状态库 |

建议下一轮优先做“**逐组件文档 + 浏览器 / 无障碍回归 + 公共 API 契约**”。相较继续增加装饰、动画或大量业务功能，这三项更能提升组件库的可信度与可采用性。

## 五、复现命令

```bash
npm ci
npm run dev
npm run check
npx playwright install --with-deps chromium
npm run test:e2e
# 一次执行 Node 检查、构建、浏览器回归：
npm run check:all
```

开发服务器默认端口 5173，可通过 `HOST`、`PORT` 环境变量覆盖。页面可直接静态部署，无需应用服务端。
